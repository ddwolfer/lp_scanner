# D66：日報加「每日手續費收入」，每日切點為台灣 06:00

## 背景
使用者要在 Telegram 日報看到「過去一天六個頭寸各賺多少手續費、合計多少」。目前頭寸快照由 07:30 的掃描在池子抓完後才寫（實際約 08:30–09:00 台北），且手動 `pnpm positions` 會覆蓋當天快照，切點不固定。使用者指定切點為台灣 06:00（美股正常盤 04:00 收、盤後結束，Robinhood Chain 24/5 但量集中在美股時段）。

## 做法
1. **獨立的 06:00 頭寸快照排程**：新 launchd `com.lp-scanner.positions`（`ops/`，StartCalendarInterval 06:00 Asia/Taipei），跑 `pnpm positions --snapshot`。快照表不變（`position_snapshots` PK 為 position_id+date，`taken_at` 已有）。
2. **快照寫入規則**：`runPositionsStage(..., { snapshot: 'force' | 'if_missing' })`。06:00 排程用 `force`；07:30 掃描與手動 `pnpm positions` 用 `if_missing`（當天已有快照就不覆蓋，只同步新頭寸/關閉狀態並印即時值）。這樣 06:00 那筆是當天的權威切點；06:00 排程失敗時掃描會補寫一筆（taken_at 會顯示真實時間，日報標示時數）。新頭寸（isNew）一律寫。
3. **每日手續費計算**（`listPositions` 加 `feesLastDay`）：earned(sn) = fees_cum_usd + collectedBy(sn)（既有函式，領過的費加回）。`feesLastDay = { usd: earned(latest) − earned(prev), hours: (latest.taken_at − prev.taken_at)/3600, from, to }`；只有一筆快照（昨天之後才開）→ prev 視為開倉（earned=0，from=opened_at）。閉倉頭寸不算。
4. **日報格式**（SPEC §13 範例更新）：頭寸行尾加「昨日費 +$3.57」；💼 段最後加合計行：`Σ 昨日手續費 +$13.42 / 投入 $10,170（0.13%/日，06:00→06:00）`。時數偏離 24h 超過 3 小時時在括號改印實際時數（例：`31h`）。
5. **卡片**：頭寸卡片「鏈上現值」那行加「昨日費 +$x（24h）」。
6. **測試**：feesLastDay 純計算（含領取事件、只有一筆快照、閉倉）；positionsStage 的 if_missing/force（用記憶體 DB）；formatPositions 合計行；SPEC/README 排程說明；DECISIONS D66。
7. **不做**：不改 07:30 掃描時間（403 觀察期 D64 未結束）；不改快照表結構。

## 風險
- 06:00 與 07:30 兩個 job 都會打 RPC 讀頭寸（約 60 次呼叫），可忽略。
- 手動 `pnpm positions` 不再覆蓋當天快照：使用者白天跑會看到即時值但快照留 06:00 的，dashboard「快照 日期」欄不變。要強制更新用 `--snapshot`。
