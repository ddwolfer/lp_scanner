# D70：日報合計含已關閉頭寸 + 錢包總值對淨入金

## 背景
- 日報合計（D66）的「累積手續費」「累積淨」只加總未關閉頭寸；10/6 SPCX 止盈關倉後，它的 $16.97 費、+$121.75 淨利從合計消失，使用者看到數字「變少」。
- 使用者想看「整個錢包比入金多多少」。10/7 手動對帳：TRACK_ADDRESS 與 OKX 兩個地址（提幣 0xb995…4c79、入金 0x2baf…a336）之間 USDG 淨入金 10,530.27；現值（LP 現值 + 未領費 + 錢包 USDG）11,044.97 → +$514.70，與頭寸層級累積淨 +$526 差 $11（換幣成本與 gas）。ETH 1.5 進、1.505 回 OKX（其中 1 ETH 是 EIP-7702 代付交易，`alchemy_getAssetTransfers` 的 external 類別抓不到），視為中性、不計入入金。
- MSTR #7298（9/29 搬池關倉）系統記淨 −$29.61，是用關倉前最後一筆快照估值；實際撤出 294.81 USDG + 8.55 MSTR（@160.9078）+ 費 $8.22 → 淨約 +$5.55。

## 做法
1. **合計含已關閉**：`formatFeesTotal` 改為累積手續費 = 所有鏈上頭寸（開 + 關）的已賺費；累積淨 = 已實現（關閉頭寸）+ 未實現（開著的）。關閉頭寸優先用 `close` 日誌 data 的 `net_usd` / `fees_collected_usd`（實際撤出金額），沒有才用最後快照。補 #7298 的 close 日誌（淨 +5.55、費 8.22）。年化行維持只算開著的頭寸（它是「目前部位」的效率）。
   格式：`累積手續費 +$244 · 累積淨 +$526（已實現 +$133、未實現 +$393）`
2. **錢包總值 vs 淨入金**（新的一行）：
   - 入金對手地址放 `.env` 的 `CAPITAL_COUNTERPARTIES`（逗號分隔），不進 repo（個人交易所地址）。沒設就不顯示這行。
   - `positionsStage` 每天額外讀：(a) `alchemy_getAssetTransfers` 查 TRACK_ADDRESS 與對手地址之間的 USDG（ERC20 Transfer 不受 7702 代付影響）雙向，算淨入金；(b) 錢包 USDG 與白名單股票代幣餘額（`alchemy_getTokenBalances`），股票用最新池價估值；ETH 只當 gas，不計。
   - 寫進新表 `wallet_snapshots(date, wallet_usd, lp_usd, lp_fees_usd, net_deposit_usd, taken_at)`；06:00 force / 其他 if_missing，同 D66 頭寸快照規則。
   - 日報：`錢包 $11,045 vs 淨入金 $10,530 → +$515（+4.9%）`；錢包 = 錢包代幣 + LP 現值 + 未領費。
   - 沒有 ALCHEMY_KEY 或查詢失敗：這行不顯示並在 log 記一筆，不影響其他段落。
3. **測試**：合計含關閉頭寸（日誌優先、快照退回）、已實現/未實現拆分；淨入金加總純函式（雙向、只算 USDG、對手地址大小寫）；錢包行格式與缺資料時不顯示。
4. **不做**：dashboard 的錢包總值卡片（下一步）、ETH 與其他鏈資產、借款餘額（借款在 OKX，不在這個錢包）。
