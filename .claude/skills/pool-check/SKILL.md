# pool-check：看池、選池、評區間

在 `/Users/pochenkuo/AI/lp_scanner` 執行，全部唯讀。

## 1. 一檔股票的所有池
```
pnpm pool <SYMBOL>            # 例：pnpm pool TSLA
pnpm pool <poolId>            # 單一池
pnpm pool <SYMBOL> --live     # 另外上鏈算最近 24h：交易者數、LP 地址數、費率分布（前 3 個池，需 ALCHEMY_KEY）
```
判讀順序（每一項都是過去實際踩過的坑）：
1. **hook**：「流動性型」一律不碰；「純費率」可放行但費率會變。
2. **費/TVL/日** 才是每塊錢的收益，不是 APR 也不是 TVL。同一股票不同費率的池直接比這個。
3. **熱度 6h** < 0.5× 表示昨天的量已冷，24h 數字高估。
4. **單時佔比** > 50% 表示收益來自一次性事件（XOM 5% 池案例）。
5. **偏離** > 1% 表示套利不緊或參考價異常（週末常見，D40）。
6. **小時資料時數**：< 72h 的池所有年化都不可信；v3 池 9/4 才加入。
7. **容量**：投入超過容量會稀釋自己；SPCX 案例：其他 LP 也擠在現價旁，窄區間份額只有 0.16%。
8. **回本天數** > 7 天的小倉位不值得開。

## 2. 開倉前評一個區間
```
pnpm range <poolId> <下限> <上限> [投入]     # 例：pnpm range 0x319bac… 115 175 645
```
看四件事：歷史待在區間的比例與出去次數、以現價開倉的兩邊配比（偏上方 = 多 USDG，偏下方 = 多股票）、模擬每日手續費與平均份額、容量與回本。
提醒使用者：往下出區間 = 全部變股票（要能接受抱著）；往上出區間 = 全部變 USDG（等於分批止盈）。

## 3. 回答格式
先給結論（選哪個池、區間有沒有問題），再用表格列數字，最後一句話講最大的風險。數字只有幾天資料時一定要說明「年化不可信，等一週」。
